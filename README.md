## Urbilote | Full Stack Software Engineer
`12/2024 to Present` · SaaS · Complex domain modeling · High volume ingestion · AWS

I develop the platform end to end. The core challenge is translating municipal urban planning legislation into a reliable calculation model that can handle different cities, zones, uses, roads and legal constraints.

### What matters technically

* Designed a modular Node.js and Express backend with services, validators, repositories and a relational model with **20+ connected tables and N:N relationships**.
* Built the calculation engine that resolves hierarchical rules across location, zoning, use and road type, including fallbacks, interdependent parameters and legal observations.
* Built ingestion flows for very large regulatory datasets with **hundreds of thousands of records**, using parsing, normalization, validation, caching, asynchronous queued processing, transactions, rollback and audit logs.
* Improved calculation and data access performance with indexes, eager loading, cache for reference data, asynchronous work and lazy loading.
* Added reliability around critical operations with validation layers, retries, idempotency and traceable calculation records.
* Implemented multi tenant access models, Stripe billing and webhook based subscription synchronization.
* Built and operated deployment infrastructure with AWS, GitHub Actions/OIDC, CloudWatch, Nginx, Cloudflare and TLS management.

<details>
<summary><b>Architecture details</b></summary>
<br>

The domain model represents relationships between states, cities, zones, allowed uses, roads, project scopes and regulatory parameters. The calculation engine resolves those relationships and applies occupancy limits, building coefficients, permeability, height constraints, setbacks and other rules in a deterministic flow.

The import layer handles complex XLSX structures with multiple sheets and hierarchical labels. It detects usable table regions, validates values before persistence, identifies conflicts and duplicates, generates reviewable previews and persists changes through controlled transactions.

The platform also has project isolation and different access modes, document versioning, legal file storage, subscription states, saved simulations and reproducible calculation history.

</details>

**Main stack:** `React` `Node.js` `Express` `Sequelize` `SQL` `Caching` `Queues` `Transactions` `Stripe` `AWS` `CI/CD`

## WhatsApp Prospect Flow | Backend Software Engineer
`06/2025 to 02/2026` · Workflow engine · State machines · Scheduling · AI · Analytics

I designed and built the backend for an internal B2B prospecting platform that had to coordinate message flows, scheduled jobs, lead state, AI classification and WhatsApp session reliability.

### What matters technically

* Modeled the lead lifecycle as a **12 state state machine** with controlled transitions and persistent funnel history.
* Built a configurable message engine with versioned flows, multiple follow up strategies, media formats and A/B variants.
* Implemented scheduling with time zone and business hour rules, plus send queues and concurrency control.
* Added status guards before scheduled jobs execute so stale jobs cannot send after the lead has moved to another state.
* Built persistent session handling, watchdogs and recovery logic around WhatsApp Web.
* Combined deterministic heuristics with LLM fallbacks for response classification, reducing unnecessary model calls.
* Built funnel and experiment analytics using response metrics, step level breakdowns and **95% Wilson confidence intervals**.
* Used caching, indexed SQL queries, batch processing, rate limiting, retries, detailed event persistence and dry run execution.

<details>
<summary><b>Reliability and AI details</b></summary>
<br>

The workflow engine cancels pending follow ups when terminal conditions are reached and keeps a full history of state transitions. Ambiguous and automatic responses can enter controlled retry flows instead of immediately terminating a prospect.

AI calls are tracked with model, token usage, task and estimated cost. Classification starts with inexpensive heuristics and escalates to models only when necessary.

The system also keeps complete message payloads for auditing and reproducibility, while scheduled work verifies the latest persisted prospect state before sending anything.

</details>

**Main stack:** `Node.js` `Express` `MySQL` `Sequelize` `State Machines` `Schedulers` `Queues` `Caching` `OpenAI` `Analytics`
